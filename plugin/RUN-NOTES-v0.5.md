# Run notes — plugin v0.5 (Handoff 18: follow Capture's selection, home actions, colour cells, labels)

Base `9e9f3ef` (v0.4.1 + the `--identify` research tool). Built and tested in a Linux sandbox against a stub CITP server. **Nothing here ran against your real Capture, Stream Deck or Mac.**

## What changed
1. **Persistent CITP session** (`src/fixtures/citpSession.ts`) replaces the brief sync. It stays connected and reconnects with back-off 2 s → 30 s (reset after a successful connection; the last good host:port is tried first, discovery/lsof again if that fails). lsof is now asynchronous so a reconnect never stalls the DMX timer. On Capture's EnterShow it sends its own EnterShow once per connection and a FixtureListRequest (retried after 5 s if no list came, then every 30 s while in the show). A FixtureList that arrives after LeaveShow is ignored. LeaveShow / a show with a different name clears the fixtures and the selection and **releases DMX**; the plugin sends LeaveShow when it exits.
2. **Outgoing allowlist**: the old list plus `FixtureIdentify`, and only a well-formed one, and the session drops every entry that is not in the caller's current set of fixtures at `0xffffffff` (checked again at the socket, with a `REFUSED …` log line). Still never sent: FixtureList, FixtureModify, FixtureRemove, FixtureSelection, FixtureConsoleStatus, SetFixtureTransformationSpace.
3. **Identification** (`identify.ts`): on every list (start, 30 s re-request, Type 1/2) fixtures still at `0xffffffff` get one FixtureIdentify. Identifiers Capture already reports are kept; new ones are the next unused numbers from 100001 up (skipping numbers in use and numbers in flight). A fixture we sent that still shows `0xffffffff` is retried with the same number, not within 5 s, at most 3 times per connection. A verifying FixtureListRequest follows 2 s after a send. Numbers we assigned resolve in selection events before Capture echoes them. Log: `Fixtures: identify: 1 of 3 fixture(s) already have an identifier; sending 2 new (100001–100002)`, later `identify: Capture confirmed N identifier(s)`.
4. **The deck follows Capture's selection**: FixtureSelection → the fixtures selected there, narrowed to the controllable ones (parsed type + valid address). One → select it; several → driven together, **each relative to its own value** (an RGB and a CMY fixture selected together each get their own attribute); none controllable → model + `No address — Setup`; an empty selection keeps the last one, marked `(not selected in Capture)`. The Select dial still picks one fixture by hand; Capture's next click overrides it. Before the first click the first controllable fixture is used (as in v0.4.1). **"All of this type" is gone.** Select-dial push/tap does nothing now.
5. **Patch changes picked up**: FixtureModify (decoded per the spec F layout) with `ChangedFields & 0x01` for an identified fixture stores universe+1 / UniverseChannel+1 in the setup if it fits and overlaps nothing; `Patched=0` clears the entry; otherwise it is refused with the reason. Logs: `Fixtures: address from Capture Ch 203 -> 1/285`, `… refused: overlaps …`. Other change bits are ignored. A modify for an unidentified or unknown fixture can't be mapped: logged, and a fresh list is requested. **FixtureModify is never sent.** If the fixture whose address moves is being driven, output is released first.
6. **Home**: the **Home Selected** key puts the selected fixture(s) only at full home (the first-touch defaults: pan/tilt 50 %, intensity 100 %, additive colours full, rest 0, shutter held). **Pressing an attribute knob** homes that attribute on the selected fixture(s). **Tapping the strip** toggles fine mode; a long touch does nothing (no home).
7. **Multi-cell colour**: the colour knobs already collected every channel carrying the colour word, so `Red 1`…`Red 5` move as one (all coarse channels, 16-bit pairs included); new test with a 5-cell fixture; pressing the knob homes all cells.
8. **No browser page**: pressing **Setup** only re-reads the show. The HTTP server, `openUrl`, `setupServer.ts`, `ui/setup-web.*`, its test and check script are deleted. The address table is in the Setup key's panel (Property Inspector, which logs `Fixtures: setup inspector opened`).
9. **Visible labels**: every key in the generated profile has `ShowTitle: true` and its name as title (the profile checker now refuses a key without it); the manifest key states are `ShowTitle: true` as well, so keys you place by hand show titles too. The plugin no longer draws label text into key images: it draws the icon, dimming, flash text (`Hold`, `Stored`), badges, and sets dynamic names (`Store 1`, position names, `Allow Access`) with `setTitle`. Icons unchanged.
10. **Strip when the Capture Channel is 0**: model on line 1, position hint (`SL 1.3 · US 0.9`) on line 2 and the address (`1/300`) on a new small line below (`layouts/select.json` got a `note` item; line 2 shrank from 17 to 16 px).
- Setup edits no longer release output unconditionally: only when the address of a fixture that is being driven moves, disappears or becomes invalid.
- Version 0.5.0 (manifest 0.5.0.0); profile regenerated (re-import it).

## NOT verified / things to know
- **On your Mac**: everything above is against a stub. In particular the real order of Capture's messages around EnterShow/LeaveShow and show changes, that Capture answers FixtureListRequest only while a show is open, and that the Stream Deck app shows the Setup panel at all (v0.4 it did not; the log line `Fixtures: setup inspector opened` will tell).
- The plugin's FixtureModify decoder follows spec F (all fields always present). **The research tool (`citp-connect --identify`) still has its provisional bit-conditional decoder**; I left it untouched, so the two disagree on a message with unchanged fields. The plugin's version is the one to trust.
- A FixtureModify carrying identifier `0xffffffff` can't be mapped to a fixture (the one you saw arrive for the unidentified fixture): it is logged and a list is requested, so that patch change is only picked up if the fixture is identified by then and the change is repeated.
- A dropped CITP connection does **not** release DMX (it reconnects; output is yours until Release/LeaveShow/show change/exit). On reconnect to the same show name nothing is cleared until a new list replaces the old one.
- Type 1/2 FixtureLists are merged by CaptureInstanceId; fixtures without one are keyed by identifier and may not merge cleanly.
- Select-dial push/tap and a long touch on an attribute strip do nothing.
- Still unverified from v0.4: real sACN into Capture, the CaptureInstanceId format, position-hint orientation, strip layout on the hardware (the new `note` line especially).
