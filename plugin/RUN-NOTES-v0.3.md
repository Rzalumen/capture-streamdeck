# Run notes — plugin v0.3.0 (Handoff 09)

Base `2ada97a` (v0.2). Built and tested in a Linux sandbox: **nothing here ran against a real Mac, Stream Deck app,
Capture, or System Events, and the generated profile has not been imported by a real Stream Deck app.** What was and
wasn't verified is listed below.

**Base / `git pull`.** `origin/main` on GitHub still ends at `4bfab97` (the research commits); the v0.1 and v0.2
commits exist only in your bundles. I rebuilt the base from `capture-streamdeck-0007.bundle` (`2ada97a`, verified) and
built v0.3 on top of it. The new bundle is cumulative like 0007 (requires `4bfab97`), so `git pull` from it in
`~/capture-streamdeck` fast-forwards whether or not you already have v0.2.

## What changed

**1. Only straight commands in the action list.**

- **Hidden, not removed** (Elgato's manifest reference: *"`VisibleInActionsList: false` … allows for the action to be
  used as part of pre-defined profiles distributed with the plugins, whilst not being available to users"*). Hidden:
  *Capture Command, Capture Tab, Camera Slot, Show Position, View Dial, View Toggle*. They keep their UUIDs and handlers,
  so keys you already placed from v0.1/v0.2 keep working; nobody can make a new one. Visible actions: 150 − 6 = 144.
- **New named actions:** `Camera: Show Position 1` … `8` (OSC auto mode, catalog 1, index k; titled from the open show;
  no settings at all), `Look: Auto Exposure`, `Look: Laser Flicker` (were `Toggle: …`; same UUIDs), `Camera: Store
  Modifier` and `Status: Connection` (were *Store Modifier* / *Connection*; same UUIDs). `Camera: Position 1–5` and
  `Camera: Store Position 1–5` already existed in the catalog (the handoff's "Store Camera: Position k" is the menu path
  `View › Store Camera › Position k`; I kept the action names).
- **Store Modifier still does something:** with the Camera Slot key hidden, *Camera: Position 1–5* now follow the modifier
  (held → `View › Store Camera › Position n`, label `Store n`, "Stored" flash; released → recall), exactly as Camera Slot did.
  This is the existing v0.2 behaviour moved onto the named keys, not a new capability.
- **Inspector:** named catalog keys: *Hold to fire* + *Dim when disabled* only (unchanged). Named toggles, Show Position,
  Store Modifier, Connection: **no inspector**. Named dials: I removed the *View* dropdown (they always drive the live
  view now) and kept the two numeric fields *Step* and *Reset value* — the handoff says named actions keep "only" hold/dim,
  which can't apply to a dial; say if you want those two fields gone too.

**2–4. Generated profile, bundled.** `npm run gen-profile` (`scripts/gen-profile.mjs`, code in `src/profile/`) writes
`com.rezabehjat.capture.sdPlugin/profiles/Capture.streamDeckProfile`, declared in `manifest.base.json`:
`Profiles: [{Name: "profiles/Capture", DeviceType: 7, Readonly: false, DontAutoSwitchWhenInstalled: false}]`
(`DeviceType` 7 = Stream Deck+ per Elgato's manifest reference). 26 pages, 182 keys. Structure follows Handoff 09 §2 exactly
(zip/deflate; `package.json`; `Profiles/<ROOT>.sdProfile/` with `manifest.json`, `Images/`, and one upper-case-UUID page
folder per page and per folder level, each with `manifest.json` + `Images/`). `AppIdentifier` = `/Applications/Capture 2026.app`,
overridable with `CAPTURE_APP_PATH`. Layout, pagination ("More ▸"), dial sets and the folder contents are as in §3
(table and full tree in `DEFAULT-LAYOUT.md`, generated by `scripts/describe-layout.mjs`). The profile is deterministic
(fixed UUIDs derived from page paths, fixed zip timestamps), so the bundled file can be compared byte-for-byte with the
generator's output. `npm run add-profile` is kept (it now also writes a `profiles/CUSTOM` marker so generation and the
comparison test leave your own export alone); `npm run gen-profile -- --force` goes back to the generated one.

**Images.** `profile-art/key/*.png` (78) and `profile-art/folder/*.png` (11): 144×144, dark background baked in, drawn
from `src/lib/icons.ts` (the plugin's own line icons) with Chromium via `npm run images -- --profile`. Folder keys use the
category icon (Windows uses the Window glyph, Positions ▸ the existing *positions* glyph); *Back* is the existing arrow; two
new original glyphs were drawn: `more` (double chevron, for *More ▸*) and `cat-look` (horizon sun, for the Look folder).
Nothing from the reference profile or any third party was requested, copied or used; the reference was never in this session.

## Decisions you may want to overrule

1. **`ShowTitle: false` on our own actions** in the profile (folder / Back / More keys use `true`). The plugin draws each
   key's label into the key image itself (like every key it renders), so a Stream Deck title on top would print the name twice.
   The `Title` field is still filled. If you'd rather have Stream Deck titles, say so and I'll flip it (and stop drawing labels).
2. **Camera folder pagination.** The rules put 14 entries in the Camera folder → three pages, so **Store Modifier ends up on
   page 3, away from Camera: Position 1–5 (page 2)**, and a held modifier can't survive a page change. I followed the spec as
   written. Either move the modifier key next to the positions in the Stream Deck app, or use *Positions ▸ › Store Camera 1–5*
   (direct store, no modifier).
3. **Plugin block on keys too.** Every key and dial of ours carries the `Plugin` block (Name/UUID/Version from the manifest);
   the two Elgato actions don't.
4. **Two states** on the catalog keys in the profile (their manifests have two: normal / dimmed), one on the rest, mirroring
   each action's manifest.
5. **`Device.UUID`** is a placeholder string (`@(1)[4057/132/CAPTURE-DEFAULT]`, vendor/product ids of a Stream Deck+); the
   handoff says "any".

## Verified here (automated)

- `npm test` in `plugin/`: **209 tests pass** (174 from v0.2 + 35 new: layout rules, zip structure, UUID case, every
  `ProfileUUID` resolves, Back at `0,0` on every page but HOME, ≤ 8 keys / ≤ 4 dials, every image exists and is 144×144,
  every action UUID is ours and visible or one of the two Elgato UUIDs, the action list has no configurable action, named
  Show Position / Store Modifier behaviour end to end, checker mutation tests, determinism and "bundled file = generated").
  `npm test` in the repo root (22) passes.
- The generated zip is also read by the system `unzip -t` ("No errors detected") and by Python's `zipfile`.
- `streamdeck validate` passes **against Elgato's live schemas this time** (in v0.2 the sandbox couldn't fetch them; with
  `NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` it can). I checked that it rejects an unknown action property and a
  missing profile file, so it is checking what I think. `AutoInstall` (in Elgato's docs but absent from the live schema
  summary) is not set; its default is true anyway.
- `npm run pack` → `com.rezabehjat.capture.streamDeckPlugin` (0.3.0.0, 372 files, includes the profile). The inspector page
  was re-checked in Chromium with `scripts/check-inspector.mjs`.
- **A test flake from v0.2 found and fixed:** *"every named dial sends exactly its own manual address"* failed ~1 run in 2
  in the full suite on the untouched v0.2 code. Cause: the connection monitor's own `/ping` (5 s) sometimes landed
  inside a dial's capture window, and the test asserted that *every* message was the dial's. The test now ignores `/ping`;
  the plugin was not at fault. (*"Permission problems…"* timed out once in one run and not in the four full-suite runs since (all 209 pass each time); I don't
  know why — noting it rather than hiding it.)

## NOT verified (needs your Mac)

1. **That Stream Deck 7.6 imports the profile.** The format is built from the handoff's description of a real export; no
   real `.streamDeckProfile` was available to me and I did not ask for one. The things I would look at first if import
   fails or looks odd: the zip's directory entries, the `Device.UUID` placeholder, `ShowTitle:false` keys, two-state
   `States` arrays, key images on dial actions.
2. **The "accept the profile" prompt on install**, and auto-switching to it when Capture 2026 is frontmost.
3. **Hidden actions:** that Stream Deck really hides the six generic ones from the action list while keeping keys that
   were placed earlier working (Elgato's reference says so; I can't see the app).
4. Everything in v0.2's "NOT verified" list (JXA calls, real error text, dial-visibility in the action list, catalog gaps,
   worker timing) is still unverified; v0.3 didn't touch the Accessibility code. The two catalog lines and the `AX press` /
   `AX summary:` lines in the plugin log settle most of it.
